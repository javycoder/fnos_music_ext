# 多用户目录与管理员扫描

默认关闭。`FNMUSIC_TEE_SAVE_BY_USER=false` 时，下载目录、引用和绑定保持原来的单目录行为。

开启后，播放、收藏或加入歌单触发的保存会落到当前用户自己的目录。用户可以在管理页为每个用户指定 NAS 绝对路径；没有单独指定时，文件保存到：

```text
<有效全局下载根目录>/users/<SHA256(完整用户 GUID)>/
```

目录归属使用完整用户 GUID 的摘要，不使用用户名，因此同名或改名不会把两个人的文件放在一起。身份无法确认、返回 `shared` 或身份超时时，本次保存不会写入公共根目录，也不会报告保存成功。播放本身可以继续。

已有的完整音频可以作为复制来源，但不会移动、覆盖或删除另一个用户的文件。每个用户有独立的保存引用，名称形如 `cache/u_<用户摘要>__<歌曲安全标识>.ref`。旧的歌曲引用仍然只用于查找已经存在的音频，不能据此认为目标用户已经保存。

更改目录配置后，新的保存使用新目录。已经落盘的文件不会自动迁移或删除。

扫描可以配置管理员账号。管理员会话只访问官方共享曲库扫描接口，登录失败时不会改用触发保存的用户身份。收藏和加入歌单仍使用原来那位用户的登录状态写入。多用户模式下，官方曲目按实际落盘路径匹配，避免同名歌曲绑到另一个目录中的副本。

每个用户的扫描配置可以继承全局、显式禁用或单独覆盖。保存配置时只提交变更；把某个用户的目录覆盖设为空会恢复自动目录，把扫描覆盖删除会恢复继承。失效用户的配置会标出来，只有明确删除时才从配置中移除，歌曲文件仍保留。

整理必须选择一个用户，并且只处理该用户当前的有效目录，不会从公共父目录递归整理所有用户。清理在多用户模式下也只遍历已经配置或能够确认的用户目录。

管理员密码只用于登录请求，不在配置读取、日志或测试资料中回显。
