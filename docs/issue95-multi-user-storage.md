# 多用户目录与管理员扫描

默认关闭。`FNMUSIC_TEE_SAVE_BY_USER=false` 时，下载目录、引用和绑定保持原来的单目录行为。

开启后，播放、收藏或加入歌单触发的保存会落到当前用户自己的目录。用户可以在管理页为每个用户指定 NAS 绝对路径；没有单独指定时，文件保存到：

```text
<有效全局下载根目录>/users/<用户名>.<归属码>/
```

目录名由用户名和归属码组成，例如 `张三.1a2b3c4d`。点号前的用户名只方便人辨认；程序只按点号后的归属码判断目录属于谁。归属码取完整用户 GUID 的 SHA-256 摘要前 8 位；两个在用用户的归属码相同时，双方一起加长到 12 位，仍然相同就用 64 位。因此同名的两个用户不会共用目录，用户改名也不会让文件换主人。

身份无法确认、返回 `shared` 或身份超时时，本次保存不会写入公共根目录，也不会报告保存成功。播放本身可以继续。

用户名表在服务启动时从飞牛音乐官方库读取一次，运行期间不再变化。读不到官方库时，自动目录回退为 `user.<归属码>`。服务启动后新建或改名的用户，要到下次启动才用上新的目录名。

旧版用完整摘要（64 位十六进制）作为目录名。启动时，扩展会把这类目录改名为「用户名.归属码」；用户改名后，下次启动同样跟随改名。改名只改目录名：目录里的歌曲、歌词等文件内容不变，指向旧目录的歌曲引用同步改到新路径。

飞牛音乐按文件路径登记歌曲，收藏、歌单和播放历史再按曲目编号关联。目录改名后，飞牛音乐需要把登记换到新路径，这些关联才保持不变。因此旧目录的歌在飞牛音乐曲库里有登记时，扩展只在飞牛音乐运行时改名，并在改名后核对曲库登记确实已换到新路径；20 秒内没有换完，就把目录改回原名，本次启动不再尝试其它有登记的目录，下次启动再试。飞牛音乐未运行或曲库读不了时，有登记的目录本次不改名，管理页会提示，期间歌曲照常使用。扩展对飞牛音乐数据库只做只读查询。

遇到以下情况，扩展不改动任何文件，只在管理页列出该目录，交管理员处理：

- 目标名已被其它文件或目录占用；
- 同一个用户有多个能确认归属的目录，无法判断该保留哪个；
- 改名操作本身失败（权限、跨文件系统等）。

已删除用户的目录不属于任何在用用户，保持原样。改名记录保存在扩展主目录的 `user_dir_migration.json`。

改名成功后，扩展请求飞牛音乐重新扫描曲库：已配置管理员扫描时自动请求一次；使用其它扫描路径或未配置扫描时，请在飞牛音乐中手动扫描。

已有的完整音频可以作为复制来源，但不会移动、覆盖或删除另一个用户的文件。每个用户有独立的保存引用，名称形如 `cache/u_<用户摘要>__<歌曲安全标识>.ref`。旧的歌曲引用仍然只用于查找已经存在的音频，不能据此认为目标用户已经保存。

更改自定义目录配置后，新的保存使用新目录。已经保存的文件不会因此移动或删除。

扫描可以配置管理员账号。管理员会话只访问官方共享曲库扫描接口，登录失败时不会改用触发保存的用户身份。收藏和加入歌单仍使用原来那位用户的登录状态写入。多用户模式下，官方曲目按实际落盘路径匹配，避免同名歌曲绑到另一个目录中的副本。

每个用户的扫描配置可以继承全局、显式禁用或单独覆盖。保存配置时只提交变更；把某个用户的目录覆盖设为空会恢复自动目录，把扫描覆盖删除会恢复继承。失效用户的配置会标出来，只有明确删除时才从配置中移除，歌曲文件仍保留。

整理必须选择一个用户，并且只处理该用户当前的有效目录，不会从公共父目录递归整理所有用户。清理在多用户模式下也只遍历已经配置或能够确认的用户目录。

管理员密码只用于登录请求，不在配置读取、日志或测试资料中回显。
