# 安装与多源可靠性审查（2026-09-10）

## 审查范围与故障定位

审查提交 `920e70d`（LX 新源/解析验证）和 `02c6063`（CI/测试/环境合并），对照 v1.2.3 接管实现。以下修复尚未部署到用户机器。

用户日志失败在 `extend.sh` 的步骤 4：通过原 Unix socket 请求代理健康接口没有通过。三个音源服务 healthz 成功与 systemd enable 创建链接，不证明代理已绑定和完成接管。该阶段不经过 nginx，也尚未进行在线试播，不能归因于 QQ/酷我第三方解析。

确定的代码问题：

1. 外层 curl 总超时 2 秒，代理串行检查四个依赖、各允许 2 秒，可能把活代理误判为无响应。
2. `ExecStartPost` 只判断原 socket 存在，可能误用安装前的官方 socket。
3. 自动回滚先停代理再判断身份，残留 socket 文件可能阻止官方 upstream 归位，却打印回滚完成。
4. 用业务 `INVALID TOKEN` 响应判断官方身份有歧义：代理也可透传该响应。
5. 配置/依赖实际加载发生在移动官方 socket 后，启动失败可能已影响官方路径。

**具体用户那次失败的唯一根因尚未确认。** 故障时段 journal 无权限读取。本机 `/tmp/extend-run.log` 是成功记录，不能替代失败现场；当前活代理来自另一目录副本，也不能据此认定用户当时运行的是本工作树。日志版本还可能受旧 `.env` 版本覆盖。

## 本次实现

### 安装和恢复

- 无依赖 liveness 与有依赖 readiness 分开；健康检查并发且有整体截止时间。
- 项目解释器、依赖和配置先预检；代理先绑定私有临时 socket，确认进程身份后再发布到官方入口。
- 通过 Linux `SO_PEERCRED`、进程启动标识、执行文件及 socket inode 记录归属，不再用业务响应猜身份。
- 共用接管/恢复逻辑、独立的安装与状态修改锁、单一 unit 模板。
- 未知、仍活跃或已被替换的 socket 不删除；恢复必须验证，无法验证时报未完成。
- Host unit 更新后明确重启；外部目录的服务/容器不自动接管。
- 接管监督进程失败后停止子进程并尝试恢复。未知旧残留不强制清理；这种保守失败可能需要管理员在原部署目录处理。

### 音乐源与播放

- LX 默认 `kg,wy,mg,kw`。QQ `tx` 保留适配及能力报告，但没有注册播放解析链路，默认关闭。
- mg 正常搜索接入第三方回退；搜索和 URL 解析共用验证路径，保留实际档位、请求头及验证状态。
- 有限媒体探活拒绝明确错误正文；`media_verified` 仅表示有限样本通过，`completeness=unknown` 不证明完整歌曲、实际解码时长或持续授权。
- 修正网易 EAPI 协议并用独立已知向量测试。
- LX 使用整体搜索预算并保留已完成子源结果；musicdl 使用有限、每源独立的工作槽，取消等待不会释放仍在执行的任务槽。
- 搜索会话按凭据与源配置隔离，已展示结果顺序保持稳定；短期失败不按七天缓存。
- 同录音去重保留经过标题/歌手/版本/时长匹配的备用源；发送音频前有限回退，成功后重定向至实际源 GUID，避免后续 Range 落回错误来源。
- 流式缓存要求正常结束及完整响应；部分 206、错误编码和中断流不得落为正式完整文件。客户端断开时清理，不再积累无界队列。

## 验证边界

- 隔离 UDS 测试验证真实 socket 与子进程行为；systemctl/Docker 安装生命周期命令使用替身，**不是在 fnOS 的真实 PID 1 下完成了一次全安装/升级验收**。
- 本轮未修改 nginx、生产 `.env`、现有 systemd unit 或生产 socket，也未重启既有服务。
- 本轮没有进行真实远端音乐搜索/下载，不据代码注释或模拟响应宣称第三方当前在线可播。
- 真实生产依赖及镜像测试验证安装/导入/进程启动，不验证账号权限、歌曲完整性或 CDN 当前状态。
- 跨源回退要求客户端遵循 HTTP 重定向；播放已开始后不拼接不同源，跨源 seek 不回退。同一来源自行更换编码仍是上游限制。
- 搜索会话有容量和空闲期限；服务重启恢复依赖尚存的搜索元数据。没有把用户历史搜索或临时直链持久化到磁盘。
- Python 工作线程不能被安全强杀；永久阻塞会占住该源槽，但不再创建无限替代线程或排队拖垮其他源。

## 用户现场最少取证

由具备权限的维护者读取故障窗口，不要为取证先删 socket 或重装：

```bash
sudo journalctl -u fnmusic-ext.service --since '故障前两分钟' --until '回滚后一分钟' --no-pager -o short-precise
sudo systemctl cat fnmusic-ext.service
sudo systemctl show fnmusic-ext.service -p Result -p ExecMainCode -p ExecMainStatus -p NRestarts -p WorkingDirectory -p ExecStart
sudo ss -xlpn
ls -li /var/run/trim_music.socket /var/run/trim_music_upstream.socket
```

核对进程是否绑定成功、退出异常类型，以及故障时 healthz 请求耗时。不要发送整个 `.env`、账户 Cookie 或 API Key。没有这些证据，不能把“扩大超时后正常”写成已经证实的原始根因。
